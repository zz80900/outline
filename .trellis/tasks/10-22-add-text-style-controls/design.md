## Context

Outline 的文档权威数据是 Y.js 协作状态和 ProseMirror JSON，Markdown 是异步生成的文本镜像及导出格式。当前 Markdown 解析器关闭了任意 HTML，因此 `<font>` 或 `<span style="...">` 不会形成可编辑的结构化样式；选择工具栏也只提供语义化行内格式。

该变更需要同时覆盖编辑器 schema、Markdown 受控解析、HTML DOM 解析、序列化、协作版本兼容和选择工具栏。由于新增 ProseMirror Mark 会改变协作文档 schema，客户端与服务端必须使用相同的编辑器主版本。

## Goals / Non-Goals

### Goals

- 支持为选中文本独立设置文字颜色和数值字号，并支持恢复继承的默认值。
- 安全解析和序列化受控 `<span>`，保证 Markdown、ProseMirror JSON、Y.js、HTML 与 PDF 路径中的样式可往返。
- 保持任意原始 HTML 默认关闭，只接受明确白名单中的属性和值。
- 在混合选区、协作编辑、只读模式、代码内容和移动端工具栏中提供一致行为。
- 通过编辑器主版本升级阻止不理解新 Mark 的旧客户端编辑相关文档。

### Non-Goals

- 不支持 `<font>` 标签，也不生成 `<font>` 输出。
- 不开放通用 `style`、`class`、`id` 或任意 HTML 标签解析。
- 不支持字体族、背景色、透明度、渐变、CSS 变量、非 `px` 单位或超出允许范围的 CSS 长度。
- 不为历史文档执行数据迁移或批量重写。
- 不在评论编辑器或其他精简编辑器中启用该能力。

## Decisions

### 使用两个独立的 ProseMirror Mark

新增 `text_color` 和 `font_size` 两个 Mark，而不是使用包含多个属性的复合 Mark：

- `text_color` 保存规范化的六位十六进制颜色，例如 `#E5484D`。
- `font_size` 保存 `8` 至 `96` 的整数，单位固定为 `px`；默认字号由不存在该 Mark 表示，并继续继承正文、标题或当前容器的字号。

字号输入步长为 `1`，Mark 属性只保存数值，不重复保存单位。两个 Mark 可独立应用、覆盖和清除，避免修改字号时意外丢失文字颜色。

备选方案是单一 `text_style` Mark，但这会增加属性合并、部分清除和混合选区判断的复杂度，不采用。

### 使用显式设置与清除命令

新增通用的 `setMark` 和 `unsetMark` 命令供值型 Mark 使用，不复用现有的布尔型 `toggleMark` 语义。用户在混合选区选择某个颜色或字号时，命令会将整个可编辑选区统一为目标值；选择“默认”时只移除对应 Mark。

新增选区读取辅助方法，用于区分统一值、混合值和未设置值，并将结果提供给工具栏状态展示。命令和状态计算跳过不允许这些 Mark 的内容。

### 只解析受控 `<span>` 子集

规范输出使用以下形式：

```html
<span data-text-color="#E5484D" style="color: #E5484D">文本</span>
<span data-font-size="18" style="font-size: 18px">文本</span>
```

两个样式同时存在时可由 ProseMirror 序列化为嵌套 `<span>`。DOM 解析优先读取 `data-text-color` 和 `data-font-size`，并兼容读取严格受限的 `color`、`font-size` 行内样式。解析规则允许同一个 `<span>` 产生两个 Mark。

颜色输入仅接受可安全规范化为不透明六位十六进制的值；字号仅接受 `8` 至 `96` 的整数，并只兼容精确的 `px` 样式输入。无效值、其他单位和不支持的属性被忽略，但保留标签内文本。事件属性、URL、表达式、CSS 变量、透明度和其他 CSS 声明不会进入 schema，也不会被重新输出。

Mark 属性校验同时用于 DOM、Markdown 和 ProseMirror JSON 反序列化，避免未经验证的值拼接进 `style`。

### 为 Markdown 增加专用行内规则

保持 `markdown-it` 的任意 HTML 解析关闭。新增共享的行内规则，只识别受控 `<span>` 开始和结束标签，将有效属性转换为 `text_color_open/close` 和 `font_size_open/close` token。Mark 的 Markdown 解析规则消费这些 token，序列化规则生成规范 `<span>`。

解析器对嵌套、组合和格式错误的标签维护严格的配对状态。无法识别或不完整的样式标签不创建 Mark，且不得丢失其可见文本内容。

备选方案是开启 `markdown-it` 的 `html` 选项后统一清洗，但这会扩大攻击面并改变现有 Markdown 行为，不采用。

### 在现有选择工具栏中增加两个控件

在默认格式化菜单的基础行内格式区域增加：

- 字号输入：数值输入框、固定 `px` 单位提示和恢复默认操作。
- 文字颜色菜单：默认颜色、预设颜色和无透明度的自定义颜色选择器。

字号输入框限制为 `8` 至 `96` 的整数、步长为 `1`，按 Enter 或失焦时提交。统一的自定义字号显示具体数值；没有 `font_size` Mark 时显示“默认/继承”，不假定正文和标题具有相同字号；混合选区显示混合占位。清空输入或选择恢复默认只移除 `font_size` Mark，非法或未完成的输入不修改文档。

控件提供明确的恢复默认操作，并沿用现有工具栏的键盘导航、提示文本、移动端菜单和禁用状态。颜色选择器从现有高亮色选择器中提取可复用的 Mark 颜色选择逻辑，避免重复实现弹层、最近颜色和颜色输入行为。

控件在只读编辑器、行内代码、代码块以及不适合应用行内 Mark 的多单元格选区中隐藏或禁用。`Code` Mark 和代码节点显式排除两个新 Mark。

### 仅在完整文档编辑器中注册扩展

两个 Mark 注册到 `richExtensions`，因此文档、分享、修订、演示和服务端渲染使用同一 schema。评论和其他精简编辑器暂不注册，避免无产品需求的能力扩散。

### 升级编辑器主版本

编辑器版本从 `17.0.0` 升级到 `18.0.0`。沿用现有协作与 API 版本校验，拒绝不支持新 Mark 的旧主版本客户端加入编辑会话。现有文档无需迁移；未使用新样式的内容保持不变。

## Risks / Trade-offs

- **Markdown 可移植性**：部分外部 Markdown 消费者会清除或显示 `<span>` 源码。通过输出稳定、最小的受控标记降低差异，但无法保证第三方渲染器保留样式。
- **颜色对比度**：自定义前景色可能在不同主题下对比不足。预设色需要覆盖明暗主题并经过可访问性检查，自定义色保留用户选择但不承诺自动满足对比度。
- **极端字号导致布局变化**：数值输入比固定档位更灵活，也更容易破坏行高和表格布局。通过 `8–96px` 整数范围、输入边界提示和导出测试限制影响。
- **格式错误的嵌套标签**：自定义行内解析规则增加边界情况。通过严格配对、无效样式降级和解析往返测试控制风险。
- **混合选区行为**：值型 Mark 不能使用简单 toggle。通过显式 set/unset 命令和统一的选区状态辅助方法消除歧义。
- **协作兼容性**：新增 schema 类型不能被旧客户端理解。主版本升级会中断新旧版本混编，但能避免未知 Mark 导致的数据损坏。
- **渲染路径差异**：外部清洗器可能剥离 `style`。规范输出同时包含受控 `data-*` 属性和等价 `style`，内部解析优先使用 `data-*`，并对各导出路径增加集成测试。

## Migration Plan

1. 同一版本发布服务端和 Web 客户端的 schema、命令、解析规则与工具栏。
2. 将编辑器主版本升级到 `18.0.0`，部署后由现有版本门禁阻止旧客户端继续编辑。
3. 不回填历史数据；旧文档在首次使用样式前保持原有 JSON 和 Markdown 内容。
4. 新样式写入后由现有 Y.js 与 ProseMirror 持久化流程保存，并由 Markdown 镜像任务生成规范 `<span>`。
5. 回滚时必须同时回滚客户端与服务端，并继续阻止不理解新 Mark 的客户端读取可编辑状态；若生产文档已包含新 Mark，不得直接降级 schema，需先发布仅禁用创建入口但仍能读取 Mark 的兼容版本。

## Open Questions

- 预设前景色的最终色板需在实现阶段依据现有主题 token 和明暗主题对比度确定；数据格式、校验规则和自定义颜色行为不受该视觉选择影响。
